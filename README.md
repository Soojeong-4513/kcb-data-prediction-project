# KCB data prediction project

학습을 마친 다섯 모델(HGB, XGBoost, TabM, xRFM, TabPFN 3.5)과 고정된 앙상블 가중치로 새 CSV의 `TARGET`을 예측하는 과제 제출 자료입니다. 실행할 때 다시 학습하지 않습니다.

**실행은 아래 제출 ZIP v2에서 시작합니다.** GitHub는 파일을 제공하며, 웹페이지의 노트북 미리보기에서 예측을 실행하지는 않습니다. 본인 컴퓨터 또는 서버에 환경과 모델을 준비한 뒤 노트북을 실행합니다. 다운로드에는 GitHub 계정, 로그인, GitHub CLI(`gh`)가 필요하지 않습니다.

- [제출용 노트북·실행 코드 ZIP v2 다운로드](https://github.com/Soojeong-4513/kcb-data-prediction-project/releases/download/r019173-full12-20261020/R019173_submission_v2.zip)
- [모델 파일을 포함한 전체 릴리스](https://github.com/Soojeong-4513/kcb-data-prediction-project/releases/tag/r019173-full12-20261020)

`Code → Download ZIP`, `Source code (zip)` 또는 저장소 첫 화면의 개별 파일 대신 **`R019173_submission_v2.zip`**을 사용하세요. ZIP에는 실행 코드·노트북·설치 스크립트·안내서·예제가 들어 있습니다. 약 19.24GB의 모델은 아래 준비 명령이 릴리스의 분할 파일 49개를 자동으로 내려받아 복원합니다. 이전 `R019173_submission_v1.zip`에는 공개 전환 전의 인증 절차가 남아 있으므로 v2를 사용하세요.

## 실행 환경

| 항목 | 준비 조건 |
| --- | --- |
| 운영체제 | Linux x86_64 |
| Python | 설치 명령을 실행할 호스트 Python 3.10 이상과 `venv` 기능. 스크립트가 전용 CPython 3.14.4를 설치합니다. |
| 메모리 | RAM 64GB 이상 권장. 실행 직전 사용 가능한 RAM 42GiB 이상 필요. |
| 저장 공간 | 설치를 시작할 때 여유 디스크 100GB 권장. 설치 후 추론 직전에도 22GiB 이상 필요. |
| 인터넷 | 최초 환경 설치와 모델 다운로드에 필요. 준비 후 예측은 오프라인으로 실행할 수 있습니다. |
| GPU | 필수가 아닙니다. 기본값은 CPU입니다. |

64GB와 100GB는 여유를 둔 준비 기준이며 검증된 최소 사양이 아닙니다. Windows 네이티브와 macOS/Apple Silicon 네이티브 실행은 지원 대상이 아닙니다. Intel/AMD Windows의 WSL2 Linux는 가능한 실행 경로이지만, WSL2에 충분한 자원을 할당한 뒤 해당 컴퓨터에서 별도로 확인해야 합니다. 교수님 컴퓨터 자체에서 실행을 확인한 상태는 아닙니다.

GPU 모드는 CUDA와 호환 드라이버가 필요하고, 사전 검사에서 여유 VRAM 50GiB 이상을 요구합니다. 기존 GPU 검증 장치는 약 96GB GPU이므로 더 작은 GPU에서의 실행을 보증하지 않습니다.

## 1. ZIP을 풀고 실행환경과 모델 준비

제출 ZIP을 쓰기 가능한 폴더에 풀고, 터미널에서 **`submission.ipynb`가 있는 폴더**로 이동합니다. 이후 명령은 모두 그 폴더에서 실행합니다.

```bash
python3 setup_environment.py --bootstrap-python
python3 prepare_models.py
python3 launch_notebook.py
```

첫 명령은 패키지 안에 전용 Python과 버전이 고정된 라이브러리를 설치합니다. 두 번째 명령은 모델 파일의 SHA-256을 확인하고 `artifacts/`에 복원합니다. 다운로드가 중단되면 같은 명령을 다시 실행할 수 있으며, 이미 검증한 분할 파일은 재사용합니다. 세 번째 명령은 전용 커널을 사용하는 JupyterLab을 엽니다. 설치·다운로드·파일 검사에는 시간이 걸립니다.

기존 연구실의 계정, SSH 접속, 소스 폴더, 가상환경 또는 캐시를 지정할 필요가 없습니다. 다른 컴퓨터에 전달할 때는 설치된 `.venvs`를 복사하지 말고 ZIP에서 새 환경을 설치하세요.

## 2. 먼저 예제로 실행 확인

JupyterLab에서 `submission.ipynb`를 열고 설정을 바꾸지 않은 채 **Run All**을 실행합니다. 기본값은 CPU와 128행 예제입니다. 마지막 셀에서 예제 기대 결과 비교 및 출력 검사를 통과하는지 확인합니다.

예제는 정답이 없는 합성 입력입니다. 기대 결과와의 일치는 실행 재현성을 확인하며 새 데이터의 예측 성능을 뜻하지 않습니다.

## 3. 새 test data에서 TARGET 생성

헤더가 있는 UTF-8 CSV를 준비합니다. 필수 설명변수 558개의 이름은 ZIP 안의 `input_schema.json`에서 확인할 수 있습니다.

- 필수 열의 순서는 달라도 됩니다.
- 입력에 `TARGET`이 있다면 제거합니다.
- `LNMON`은 있어도 되고 없어도 됩니다.
- 임의의 식별자나 추가 열, 중복 열을 넣지 않습니다. 필수 열이 빠져 있으면 중단합니다.

예를 들어 패키지 폴더 안에 `data/test.csv`를 두었다면 노트북 첫 번째 코드 셀의 `INPUT_CSV`를 다음과 같이 바꾸고 **Run All**을 실행합니다.

```python
INPUT_CSV = "data/test.csv"
```

절대 경로도 사용할 수 있습니다. 첫 번째 셀에서 실제 적용된 입력 경로와 CPU/GPU 모드를 확인하세요.

완료되면 마지막 셀의 **최종 결과**에 출력 파일의 전체 경로가 표시됩니다. 기본 위치는 다음과 같으며 매 실행마다 새 출력 폴더가 생성됩니다.

```text
패키지 폴더/
└── outputs/
    └── run_<실행 시각>/
        ├── predictions.csv
        ├── diagnostics.csv
        └── report.json
```

**`predictions.csv`가 최종 결과입니다.** 입력과 같은 행 수·행 순서로 `TARGET` 단일 열을 저장하며 값은 0 또는 1입니다. `diagnostics.csv`에는 모델별 확률과 앙상블 확률, `report.json`에는 실행 기록이 저장됩니다.

명령행에서도 새 데이터를 예측할 수 있습니다. 이미 있는 출력 폴더를 지정하면 덮어쓰지 않고 중단하므로 새 이름을 사용하세요.

```bash
python3 predict.py --input "/absolute/path/to/test.csv" --output outputs/test_001 --mode cpu
```

## 검증 상태와 문제 해결

**v2 공개 다운로드·독립 실행 검증 통과 (2026-10-20).** GitHub 계정·토큰·CLI 없이 공개 릴리스의 49개 분할 파일(19,240,846,631바이트)을 실제 다운로드하고, 해시를 확인하여 31개 모델 파일로 복원했습니다. 기존 연구실 폴더와 인터넷을 차단한 상태에서 제출 노트북 전체를 실행했습니다.

- CPU 128행: 패키지 밖의 새 CSV 경로, UTF-8 BOM, 열·행 순서 변경, LNMON 생략을 적용하여 기준 결과와 비교했습니다.
- GPU 4,097행: 다섯 모델과 앙상블 확률 및 최종 TARGET을 기존 기준 결과와 비교했습니다.
- 새 수치값·결측값·처음 보는 범주·모든 값이 결측인 행·중복 행이 있는 17행, 단일 행, 0행 입력에서도 결과 파일 생성을 확인했습니다.
- 결과는 입력 순서의 TARGET 0/1 한 열입니다. 상세한 수치·검증 범위는 제출 ZIP 안의 `VERIFICATION_KO.md`와 `evidence/v2/`에 있습니다.

확인한 입력 규모를 넘어서는 임의 크기의 파일이나 모든 운영체제·컴퓨터에서 실행된다는 보증은 아닙니다. 실행 환경이 다르면 운영체제와 RAM 정보를 알려주시면 맞는 실행 방법을 확인할 수 있습니다.

오류가 나면 노트북의 메시지를 먼저 확인하세요. 예측을 시작한 뒤 실패한 경우 출력 폴더의 `failure.json`과 각 모델 폴더의 `process.log`에 상세 기록이 남습니다. 메모리·디스크 검사나 파일 무결성 검사를 우회하지 마세요. 모델 복원 상태만 확인하려면 다음 명령을 사용합니다.

```bash
python3 prepare_models.py --verify-only
```

자세한 설치·오프라인 모델 복원 방법은 ZIP 안의 `README_KO.md`, 빠른 실행 순서는 `QUICKSTART_KO.txt`에 있습니다. 모델 및 외부 코드의 사용·재배포에는 동봉된 라이선스와 고지문이 적용됩니다.
